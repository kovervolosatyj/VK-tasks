# Black Myth: Wukong Benchmark Tool — автоматический запуск CPU- и GPU-теста (C#)

Консольное приложение на C# (.NET 8, Windows). Само настраивает бенчмарк, дважды запускает его из Steam
(CPU-проход и GPU-проход), дожидается окончания, считывает результаты с экрана и печатает отчёт
(консоль + `results\<дата>\report.md` + скриншоты).

## Требования
- Windows 10/11, Steam запущен и выполнен вход в аккаунт.
- Установлен **Black Myth: Wukong Benchmark Tool** (бесплатный, AppID `3132990`) и **запущен вручную хотя бы один раз** (чтобы появился `GameUserSettings.ini`).
- Visual Studio 2022 с .NET 8 SDK.
- Для OCR в Windows должен быть установлен русский или английский язык (Параметры → Время и язык).
- Запускать от **обычного пользователя** (не от администратора). Монитор — основной, игра в режиме «окно без рамок» (так по умолчанию).

## Запуск
1. Открыть `WukongBenchmark.csproj` в Visual Studio 2022 (NuGet-пакеты восстановятся сами).
2. Режим **Release**, `Ctrl+F5`. Либо в консоли: `dotnet run -c Release`.
3. Если тул установлен в нестандартную библиотеку Steam и не найден автоматически:
   `WukongBenchmark.exe "D:\SteamLibrary\steamapps\common\Black Myth Wukong Benchmark Tool"`
4. Во время теста **не трогайте мышь и клавиатуру** и не открывайте другие окна. Если кнопку запуска найти не удалось,
   программа попросит нажать её вручную и подтвердить Enter в консоли.

Ваши настройки бенчмарка сохраняются в `GameUserSettings.ini.orig` и возвращаются на место после теста.

## Как это работает
1. **Характеристики ПК** — WMI (CPU, GPU и драйвер, RAM, ОС, разрешение экрана).
2. **Настройки** — правится `...\b1\Saved\Config\Windows\GameUserSettings.ini` (строка `UISettingData`, секции `ScalabilityGroups`, `RayTracing`, `GSRenderSetting`). Значения взяты из файлов, которые сам тул сохранил после ручной настройки в меню, и сверены со скриншотами результатов.
3. **Запуск** — `steam://rungameid/3132990`, ожидание процесса `b1-Win64-Shipping.exe`.
4. **Вход в тест** — на заставке с логотипом программа кликает в центр окна (до 4 раз). Затем через скриншот и встроенный OCR Windows (`Windows.Media.Ocr`) находит пункт меню «Тест быстродействия» и кликает по нему. После этого игра спрашивает «Хотите запустить тест быстродействия?» — программа находит надпись «Подтвердить» и нажимает её (кнопку «Отменить» не трогает). Только после подтверждения стартует замер.
5. **Ожидание** — первые 100 с после старта программа ничего не делает (скриншоты и OCR сами нагружают систему и влияли бы на FPS). Затем раз в 4 с проверяет, появился ли экран «Результаты теста».
6. **Результаты** — тул не сохраняет результаты в файл (в `Saved` их нет), они есть только на экране. Поэтому делается скриншот, области с цифрами увеличиваются и распознаются OCR: среднее / максимальное / минимальное FPS, 5-й перцентиль, используемая видеопамять. Скриншот сохраняется рядом с отчётом для проверки.
7. **Проверка** — разрешение, прочитанное с экрана результатов, сверяется с ожидаемым; при расхождении в отчёте появляется предупреждение.

## Выбор настроек

### CPU-тест: нагрузка на процессор, влияние видеокарты минимально
Разрешение 1280×720, render scale 100% (апскейл и генерация кадров отсутствуют), трассировка выкл., размытие выкл.,
текстуры / тени / GI / отражения / сглаживание / постобработка / эффекты / материалы — «Низкие».
**Дальность прорисовки и растительность — «Высокие»**: они увеличивают число объектов, draw call'ов, работу culling'а и стриминга,
то есть грузят процессор, а видеокарте почти ничего не стоят. Всё, что нагружает GPU, минимально, поэтому кадр упирается в CPU.

### GPU-тест: максимальная нагрузка на видеокарту
Родное разрешение монитора, render scale 100% (рендер без апскейла), все параметры качества «Ультра», трассировка лучей включена
на максимальном уровне. **Генерация кадров выключена**: она искусственно меняет FPS и скрывает реальную загрузку GPU.
Процессору остаётся запас, кадр упирается в видеокарту.

**Как задаётся масштаб рендера.** В `GameUserSettings.ini` ключ `ImageQuality` — это высота внутреннего рендера. «Степень избыточной выборки» на экране результатов = `ImageQuality` / высота окна (1080 при экране 1440 = 75%). Поэтому в обоих проходах `ImageQuality` равен высоте окна: рендер идёт в 100% без апскейла.

### Как убедиться, что тест действительно «про CPU / про GPU» (рекомендую для защиты решения)
- CPU-тест: во время прохода загрузка GPU заметно ниже 100%, а при дополнительном снижении render scale FPS почти не растёт.
- GPU-тест: загрузка GPU близка к 100%, а FPS заметно падает при росте разрешения.

## Ограничения и что проверить на другом компьютере
- Разрешение в туле задаётся парой `ScreenResolution` + `WindowFullImageQuality` как **доля от родного разрешения монитора** (CPU-проход: 50%, на мониторе 2560×1440 это 1280×720; GPU-проход: 100%). Поэтому настройки переносимы на другие мониторы. Если в отчёте появилось предупреждение «тул отработал на …», сверьте значения в `Presets.cs`.
- Слова для поиска пункта меню лежат в `StartButtonWords` (`Program.cs`): по умолчанию «быстродейств» и «performance». При другом языке интерфейса добавьте свои.
- Длительность паузы `BenchmarkMinSeconds` — чуть меньше, чем реальная длительность прогона; подберите секундомером.
- OCR может ошибиться в цифрах: если FPS не прошёл проверку (`min ≤ 5% ≤ avg ≤ max`), в отчёте будет пометка — сверяйтесь со скриншотом.
